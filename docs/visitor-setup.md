# Visitor tracking setup

## Do I need my own server?

**No.** Supabase is a *hosted* service — you sign up, it gives you a Postgres
database and a REST API over HTTPS. There is nothing to install, nothing to keep
running, and no card required on the free tier.

The free tier gives you **500 MB of database and unlimited API requests**, which
for a personal homepage is years of headroom: a visit row is roughly 200 bytes,
so 500 MB is about **2.5 million visits**.

### Free options, compared

| Service | Free tier | Effort | Notes |
| --- | --- | --- | --- |
| **Supabase** ← used here | 500 MB Postgres, unlimited API calls | sign up, run one SQL block | REST API with CORS, works straight from the browser |
| **Neon** | 0.5 GB Postgres | sign up | also Postgres; you would need a small serverless function since it has no browser-facing REST layer |
| **Turso** | 9 GB, 500 M row reads/mo | sign up | SQLite at the edge; same caveat about needing a function |
| **Firebase (Firestore)** | 1 GB, 50 k reads/day | sign up | works from the browser directly, but a heavier SDK |
| **Cloudflare D1** | 5 GB | needs a Worker | only worth it if the site already lives on Cloudflare |

If you would rather not manage **any** of this, the drop-in widgets
[MapMyVisitors](https://mapmyvisitors.com/) and
[LiveTrafficFeed](https://livetrafficfeed.com/) give a visitor map plus a
country/city breakdown with zero setup. They deliberately do **not** expose raw
IP addresses — which, now that you don't want IPs anyway, makes them a perfectly
reasonable alternative.

## Supabase setup

### 1. Create a project

Sign up at <https://supabase.com> (free, no card) and create a project.
Any region is fine.

### 2. Create the table

Open **SQL Editor** and run this once:

```sql
create table if not exists public.visits (
  id           bigint generated by default as identity primary key,
  created_at   timestamptz not null default now(),
  city         text,
  region       text,
  country      text,
  country_code text,
  lat          double precision,
  lon          double precision,
  path         text,
  referrer     text,
  ua           text
);

-- newest-first reads are the only query pattern
create index if not exists visits_created_at_idx
  on public.visits (created_at desc);

alter table public.visits enable row level security;

-- the browser may insert (that is how tracking works)
create policy "anon can insert visits"
  on public.visits for insert
  to anon
  with check (true);

-- and may read, so the dashboard can render
create policy "anon can read visits"
  on public.visits for select
  to anon
  using (true);
```

Note there is **no `ip` column** — the address is used once for the geolocation
lookup and then thrown away. Nothing personal is stored.

### 3. Copy the credentials

**Project Settings → API**:

| Supabase field      | goes into     |
| ------------------- | ------------- |
| Project URL         | `supabaseUrl` |
| `anon` / public key | `supabaseKey` |

Paste them into `js/visitor-config.js`:

```js
window.VISITOR_CONFIG = {
  supabaseUrl: 'https://abcdefghijklmnop.supabase.co',
  supabaseKey: 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...',
  fetchLimit: 1000,
};
```

The `anon` key is meant to be public — row level security is what protects the
data, and the policies above deliberately allow anonymous insert and read.

### 4. Deploy

Commit and push. Every page view from then on is recorded and shows up on the
homepage (bottom) and on `/visits`.

## Notes and caveats

**Privacy.** Only city, region, country, page path, referrer and user-agent are
stored. No IP addresses, no cookies, no third-party advertising. That keeps you
well clear of the usual GDPR / PIPL concerns around IP addresses.

**Spam.** Anonymous insert is open by design, so anyone who reads the page source
could script junk rows. If that happens:

- add a Supabase Edge Function that checks the `Origin` header before inserting
- or periodically prune: `delete from visits where created_at < now() - interval '180 days';`

**Row limits.** The dashboard fetches at most `fetchLimit` rows, newest first.

**Map tiles.** The map uses Esri's "World Light Gray Canvas" basemap, which needs
no API key. If you ever want a different look, swap the `L.tileLayer(...)` URL in
`js/visits.js` — but avoid CARTO's `basemaps.cartocdn.com`, which now stamps
"API KEY REQUIRED" across every tile unless you register.
